# Plan Prompt

Using the business case and `docs/design/specification.md`, complete `docs/design/plan.md` for the **School IT Support Knowledge Hub**.

Use the existing `plan.md` template and `docs/design/reference/plan-guide.md`.

Requirements:
- Maintain the original plan template structure.
- Make every meaningful decision trace back to requirement IDs in the specification.
- Adapt the existing starter application instead of proposing a rewrite.
- Keep the existing Bootstrap-based styling and route structure unless a requirement needs a change.
- Use `items-template.csv` as the prototype data source.
- Focus on a working front-end prototype before any database or backend work.
- Do not add authentication, admin dashboards, ticketing, or unrelated features.
- Use plain, clear language.
- State assumptions where something is not fully decided.
- Include realistic risks and mitigations.
- Sequence work in a sensible dependency order.
- Record meaningful choices as ADRs with at least one alternative considered.

Before finalizing, verify:
- Every ADR cites requirement IDs.
- Every component maps to at least one requirement.
- Every risk includes a mitigation.
- Sequencing follows dependencies and uncertainty.
- No major feature was invented outside the specification.
