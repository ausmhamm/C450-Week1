# Tasks Prompt

Using `docs/design/plan.md`, `docs/design/specification.md`, and `docs/design/reference/tasks-guide.md`, complete `docs/design/tasks.md` for the **School IT Support Knowledge Hub**.

Focus on adapting the existing starter application into a working front-end prototype.

Rules:
- Preserve the `tasks.md` template structure.
- Every task must trace to at least one R# or ADR#.
- Start each task with a clear action verb.
- Keep tasks small enough to finish in under one day.
- Make each task checkable.
- Order tasks according to `plan.md`.
- Reuse existing starter code whenever possible.
- Include tasks for CSV data, navigation, collection cards, detail view, bookmarking, error handling, styling, and testing.
- Do not add authentication, a database, ticketing, or unrelated backend work.
- Keep initial status as `Not started`.
- Leave Blocked / Questions empty unless there is a real blocker.

Before finalizing, verify every task is small, checkable, ordered, and traceable.
